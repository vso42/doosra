doosra lists, for every pair liqind routes, roughly how much you can sell before the price slips 1, 2, 3, 5 or 10 percent, grouped by chain. The numbers come from our own router run against a saved block on each chain, so they are model estimates rather than executed trades. The page is plain HTML: `build.py` reads the input files in `data/`, which are not in this repo, and writes `docs/`, which GitHub Pages serves at https://vso42.github.io/doosra/. The numbers shown on the page are also in `docs/data/figures.json`.

The current publication keeps audited corrections and preserves earlier public estimates wherever an updated result is still missing. Earlier estimates are labeled in the hover text and pinned to the original published file; they are not presented as corrected reruns. Updated, audited figures take priority. At an identical input, a worse solver candidate cannot replace a better freshly checked feasible quote. Saved capture and research files remain available for reproducibility.

The reviewed publication includes the quantity-funded recovery corrections, the PYUSD → GHO converter-bridge correction, four strict input-domain repairs, and fresh WETH → LINK results for all five bands. Prepare updates with `scripts/prepare_incremental_integrity_site.py` in the full project, review its staged manifest and audit, then replace the active input files with that audited stage. Run `.venv-dexrouter/bin/python site/build.py` from the project root and push `site/docs/`. Older exporters that remove pending estimates should not be used for the current publication policy.

The full catalogue audit and rerun are recorded separately in `investigations/all-pair-integrity-20261019/`; this publication does not claim that work is complete. These are funded model estimates with recorded pool-coverage and optimality limits, not whole-route execution proofs.
